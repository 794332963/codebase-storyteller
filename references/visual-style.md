# 视觉与交互规范

## 总体风格

- 只使用 Light 主题：页面背景白色，正文深灰，禁止深色段落、深色代码块、暗色 SVG 背景。
- 接近 Notion/Linear 的克制文档感：内容宽度稳定、层级清晰、留白充足、边框轻、阴影弱。
- 正文 `14px`，行高 1.65；标题仅用于信息层级，不使用营销式超大标题。
- 使用低饱和蓝、绿、灰、橙作为语义色：蓝表示主路径/应用层，绿表示成功或终态，橙表示异步或注意，红只表示失败/阻断。
- 卡片圆角不超过 `8px`，不要形成卡片套卡片。

建议色板：

```css
:root {
  --page: #ffffff;
  --surface: #f8fafc;
  --border: #e2e8f0;
  --text: #1e293b;
  --muted: #64748b;
  --blue: #2563eb;
  --blue-soft: #eff6ff;
  --green: #15803d;
  --green-soft: #f0fdf4;
  --orange: #c2410c;
  --orange-soft: #fff7ed;
  --red: #b91c1c;
  --red-soft: #fef2f2;
}
```

## 离线自包含原则

最终 HTML 在断网环境双击打开仍可使用：

- 所有 CSS、JavaScript、图表、图标和代码片段都在单个 HTML 内。
- 禁止 `<script src>`、`<link href>`、`img src="http..."`、PlantUML URL、Mermaid CDN、远程字体、远程图片和 fetch/XHR/WebSocket。
- 图表必须作为内联 `<svg>` 插入。可以在生成阶段使用任意辅助工具，但最终产物仅保留预渲染的 SVG。
- SVG 必须有 `viewBox`、可缩放宽度、文本替代说明 `aria-label` 或 `<title>`，并使用模板的 lightbox 交互。
- SVG 写入时必须已是最终彩色形态。禁止通过 JavaScript `innerHTML`、`appendChild`、属性循环、运行时重着色或任何后处理改变图表。
- HTML JavaScript 只允许 scrollspy 与 lightbox；禁止图表渲染器、SVG 操作、复制脚本、备用 SVG 字符串和永不执行分支。

## 图表规则

所有图独立成卡片，包含：标题、阅读提示、图本体和图例（必要时）。图下不放“来源：…”或“证据：…”行；代码出处通过图内归属小字、正文和表格中的 `.code-open` 深链表达。

### 共享构件层（两视角共用）

本节只定义与报告内容无关的原子视觉构件。业务视角与架构视角必须共用；它只能统一构件呈现，**不得改变**任一视角的章节、图类型、链路数量、状态覆盖、方法要素、图文密度或叙事方式。

- **语义色板：**使用同一套低饱和色值：主路径/入口蓝、领域/成功绿、外部/物流橙、失败/取消红、特殊/方言靛、中性灰；每种语义在两视角中使用相同色值。
- **固定 token：**入口/主路径 `#2563eb` 与 `#eff6ff`；领域/成功 `#15803d` 与 `#f0fdf4`；外部/物流 `#c2410c` 与 `#fff7ed`；失败/取消 `#b91c1c` 与 `#fef2f2`；特殊/方言 `#4f46e5` 与 `#eef2ff`；中性 `#64748b` 与 `#f8fafc`。箭头 marker 使用各自的深色 token；泳道底色使用对应浅色 token；`.step-badge` 使用 `#2563eb`；`.field-pill` 使用 `#eef2ff` 填充与 `#a5b4fc` 描边；`.async-group` 统一使用 `#fffbeb` 填充、`#f59e0b` 描边和 `5 4` 虚线。
- **箭头 marker：**每种语义色定义一套尺寸和 `refX` 一致的 marker；SVG 内的 marker、clipPath、mask 等 ID 必须按图实例隔离。
- **连线：**统一 `2–2.25px`、正交布线；实线表示同步，虚线只表示异步或依赖。标签使用对应语义色与白色描边或白底。绘制前先确定目标框/生命线坐标，终点必须落在目标可见进入区域并计入 marker `refX`，不得悬空或落框外。
- **节点框与文字：**节点使用既定圆角、语义色边框和左侧语义色条；文字不得溢出框边界或贴到右边缘。必要时只允许扩大该内容框本身，禁止自动重排相邻节点、同排节点、泳道、分区背景或既有连线。
- **结构容器：**泳道 lane/swimlane、分区背景 section-bg、虚线分组 async-group、网格背景与其他承载多个子元素的框永久豁免贴合文字、统一高度和自动重排判定；它们保持满高容器背景和原有标签位置。
- **泳道：**统一标题条、生命线虚线和多色分区；底色必须写为 SVG 节点内联 `style="fill:..."`，禁止使用 `fill` 属性。
- **复用构件：**字段胶囊 `.field-pill`、异步分组框 `.async-group`、步骤徽章 `.step-badge`、决策菱形、图例使用上述固定 token 与同一套尺寸、圆角、描边与字号。决策只允许 SVG `<polygon>` 菱形，普通步骤只允许圆角 `<rect>`，所有出边带条件标签。
- **图内分区与适配：**图表先按事实分配稳定区域，再放置元素：主同步路径、异步/重试分支、失败/补偿说明、图例分别占用不重叠的纵向或横向区域。说明块不得覆盖泳道标题、生命线、节点、连线或字段胶囊；内容超过单个区域时增加画布高度、拆分连续图或使用可滚动宽度，不能通过压缩字号、跨区叠放或裁切解决。该规则适用于所有图类型，不改变任一视角应呈现的链路、状态或叙事内容。
- **颜色控制权：**SVG 内所有颜色一律使用节点的内联 `style="fill:..."`、`style="stroke:..."`；外层 HTML/CSS 不得为 SVG 内部节点设置 `fill`。
- **HTML 构件：**`.code-open`、`.tag`（fact/inference/gap）、`.card`、`.highlight`、表格、lightbox、TOC scrollspy 均复用同一模板。每张图后不得输出 `<p class="muted">来源：…</p>`、`.evidence` 或其他图下来源/证据行。

同一报告内不得出现内容实质相同的图。若第二处需要同一对象，必须从当前章节需要的不同信息角度重新绘制，而不是复制 SVG。

### 视角表达层（互不影响）

本层只由各视角自己的规格决定。业务视角保留业务主干、实体关系、状态机、字段生命周期、上下游与 14 章叙事；架构视角保留抽象关系、调用链、决策流程、数据结构流转、扩展边界与 12 章叙事。共享构件层不得作为合并、抽样、简化或压平任何表达层规则的理由。

### 系统总览

- 优先左到右阅读。
- 用真实代码可识别的概念角色组织布局；入口、核心处理、异步、外部依赖、实体只是组织视角，不假设固定分层。
- 异步不应被隐藏在角落；标出发布与消费的真实方法。
- 系统总览优先使用自上而下的纵向层级带：同一层的组件横向排列，不同层使用不同低饱和底色；不要默认做横向长列。
- 每层包含业务职责短句、真实方法名或接口名；跨层关系走正交垂直通道，避免对角线穿过层内组件。
- 多仓库时，以清晰的泳道、分区带或带标题的边界框划分仓库；边界标题显示 `仓库名 @ 实际版本/ref`。组件标题或副标题重复标注仓库归属，避免读者在放大图外失去上下文。
- 跨仓库边从一个仓库边界的空白通道出发、进入另一个边界，使用箭头标签说明真实关系（例如调用、实现、注册、依赖或数据传递），不得用颜色或空间相邻暗示未证明关系。

### 实体关系与类型关系

- 每个实体显示名称、关键 ID、状态/跟踪字段和关键外键。
- 关系边标注真实关联字段名。
- 实体过多时按聚合/模块拆图，不能缩小字体强行塞进一张图。
- ER 图的关系边使用菱形/箭头或 crow's foot 表达基数和方向；每条实际关联都必须有可见的关系标签。
- ER 图先按实体数量分配稳定网格，再绘制边。实体框的高度必须容纳全部字段行，边标签放在独立留白区；禁止连线、标签或字段文字互相覆盖。
- 架构视角的类型关系图，以及业务视角中真实存在类型层次的关系图，使用标准 UML 记法：泛化/继承使用实线空心三角箭头；接口实现使用虚线空心三角箭头；组合使用实线与位于整体端的实心菱形；聚合使用实线与位于整体端的空心菱形；依赖使用虚线开箭头；关联使用实线箭头。
- 每条 UML 关系必须由独立 SVG path 绘制，菱形或三角 marker 位于语义正确的一端，并用关系名、字段名或注册名标注。泛型约束、嵌入、构造注入或注册调用只有在代码能证明相应关系时才绘制。
- 不因字段为对象类型就断言组合或聚合：无法从生命周期、所有权或显式组合语义证明时，使用可证明的关联/依赖，或不画该边。不得猜测基数、可选性或方向。
- 多仓库关系图使用仓库边界框分组实体或类型；跨边界关系标签同时包含关系动作和仓库归属。不同版本、底座、扩展或改造实现使用独立节点/分组，不压缩为同一个无版本节点。

### 状态机

- 一张图只表示一个实体。
- 终态使用双边框或绿色强调。
- 每条边使用触发方法名；不画无法确认的合法路径。
- 失败、取消、回退或跨行转移优先用 90 度折线路由，标签放在折线留白区；避免多条长直线平行穿过状态节点。

### 时序图

- 参与方顶部按调用方向排列，名称带仓库短名。
- 多仓库时，参与方标题使用 `仓库名 @ 版本 · 组件/方法`；每次跨仓库调用在箭头标签或独立跳转标识中明确写出源仓库与目标仓库。
- 使用明显的 `成功`、`失败`、`重试/补偿` 分段，而不是重叠的箭头。
- 一张图过大时，按“接入和校验”“持久化和外部调用”“异步收敛”拆开。
- 时序图必须采用泳道：每个参与方占固定列宽，顶部有色标题条，正文有浅色泳道底纹与虚线生命线。
- 每步使用带编号的小标签和一句真实的方法名；关键字段写入使用紧邻箭头的字段胶囊，而不是长段文本。
- 失败、重试、幂等、异步回调必须用独立的浅色分组框（`alt` / `retry` / `async`）表达，不能只在箭头旁补一行文字。
- 单图应优先呈现 6 到 12 步。如果主链路超过该范围，拆成“准备和写入”“外部调用和结果收敛”两张连续图；视觉上使用相同参与方顺序和颜色。

### 字段生命周期

- 用从左到右的阶段展示首次写入、更新条件、复制/清空、终态值。
- 状态字段和业务标识字段分开展示，避免把多类字段塞进一条不可读流程。

### 图类型专属规则

本节只定义不同图类型应承载的信息结构，不重新定义视觉样式。所有图仍遵循“共享构件层（两视角共用）”和“交付前视觉校验”。

- **架构总览图**：使用纵向分层带；层标题、组件、说明三层文字层级与系统总览一致。层与仓库分别使用低饱和底色，跨层和跨仓库边走正交通道，每条有向关系独立带箭头。
- **核心抽象/类型关系 UML 图**：先按类型数量和层次分配稳定网格再布线。类型框高度必须容纳成员行；关系标签位于独立留白通道。使用既定 UML marker、低饱和层/仓库分色、圆角和图例，禁止成员文字、标签与连线互相覆盖。
- **主干调用链时序图**：完全遵循“时序图”规则：带色泳道与顶部标题条、虚线生命线、编号步骤徽章、字段胶囊、成功/失败/重试/异步分组框、图例和最小 `12px` 字号；参与方之间的连线优先正交布线。
- **机制流程/决策图**：判断使用菱形，分支边有可读标签；流程节点使用统一圆角和语义色。先分配节点与分支的空白通道再布线，避免边交叉或穿过节点；图例说明判断、主路径和异常/替代路径。
- **数据结构构建/流转图**：从左到右按稳定阶段组织。阶段框使用可区分低饱和色，转移边带动作标签，关键字段或类型变化使用字段胶囊；阶段过多时拆为连续图，不堆成不可读长链。

### 交付前视觉校验

业务与架构视角必须达到同等级的成图质量。写入报告前，逐张图检查以下项目：

- 每个内联 SVG 都有显式的白色画布底，不能依赖浏览器默认背景；禁止深色或未定义的图表底色。
- SVG 内的 `id`（尤其是 `marker`、`clipPath`、`mask`）在整份 HTML 中必须唯一，或以图表实例前缀隔离；每个 `marker-end`/`marker-start` 都必须指向同一 SVG 中存在的 marker。
- 每条有向边独立绘制，箭头端点停在目标节点边界或时序生命线上；标签放入预留留白通道，不能压在线、箭头、节点文字或其他标签上。
- 报告内任意两张图不得描述完全相同的结构与流程；若同一对象需要再次出现，第二张图必须呈现与所在章节对应的不同信息角度。
- 含分支逻辑的流程图中，所有判断节点均为居中文字的 SVG `<polygon>` 菱形，且每条出边有条件标签；不得将判断节点画成普通圆角矩形。
- 逐条核验有向边的终点坐标：箭头必须落在目标框或时序生命线的可见进入区域，水平边对齐目标框左/右边并计入 marker `refX`，垂直边对齐目标框上/下边；不得出现悬空箭头或终点落在目标框外。
- 所有用于连线的 `<path>` 必须显式使用 `fill="none"`。开放 path 的默认填充会被浏览器自动闭合为多边形，可能在流程图中产生黑色三角或色块；marker 自身的 path 例外，必须显式声明箭头填充色。
- 节点内多行文字需要预先分配固定行距和底部留白，全部基线留在节点边界内；普通图中文字、步骤编号、图例和字段胶囊文字不得小于 `12px`。
- 每张图的主路径、异步/重试、失败/补偿和图例说明是否拥有独立且不重叠的区域；在宽屏放大、窄屏横向滚动和 lightbox 查看时，是否仍无裁切、遮挡、跨区覆盖或字号压缩。
- 内容框只执行不溢出软约束：每行文字末端必须在框右边界 `10px` 以内，最后一行必须在框底边界以内；必要时只扩大该内容框本身。结构容器永久豁免，不设置留白上限，不参与统一高度或自动重排。
- 总览图的分层带、时序图的参与方泳道、流程图的主路径/替代路径应使用可区分的低饱和蓝、绿、橙、灰或红色。不要用“白底矩形 + 黑线”替代语义配色。
- 时序图除彩色泳道外，还必须包含步骤徽章、关键字段胶囊，以及真实存在的成功/失败/异步或重试分组；不能只画若干横线和文字。
- 使用实际浏览器或本地渲染器在桌面与窄视口检查成品。若运行环境阻止本地文件截图，仍须执行结构化 SVG 检查（唯一 ID、marker 引用、显式画布、最小字号），并在完成说明中如实说明未能执行的像素级检查。

### 图元视觉冻结

图元视觉已冻结。后续只允许更新内容层（章节、事实、链路、状态、方法与证据），不得新增或调整像素级布局、自动重排、色条联动、统一高度或容器尺寸规则。

## HTML 交互

`templates/report.html` 已提供下列交互，生成报告时不要移除：

- 固定左侧目录和 scrollspy。
- 图表点击或键盘 Enter/Space 打开 lightbox。

生成内容需要：

- 每个一级章节使用稳定 `id`，并在侧边栏声明对应锚点。
- 每个可放大 SVG 包在 `.diagram-zoom` 中，带 `tabindex="0"` 和 `data-lightbox-title`。
- 表格在窄屏时放入 `.table-wrap`，保持横向滚动而非压坏布局。
- 证据脚注默认不显示；只在确实不确定的结论附近使用轻量 `.tag.gap`。
- 方法名或明确信息本身是 `.code-open target="_blank"` 按钮；按钮文字必须就是方法名/对象名，不显示“打开代码”泛化文案、fallback 命令或折叠源码。
- `.highlight` 仅用于有证据的“设计亮点”说明：使用模板提供的浅色背景与左边框，保持为正文中的轻量 callout，不做营销横幅、醒目大标题或重复卡片。
- 不提供“返回顶部”按钮。固定侧边栏目录已经覆盖页面级导航，避免在正文末尾增加无关控件。

## 可读性与无障碍

- 图中文字最小 `12px`，普通表格最小 `12px`。
- 颜色不作为唯一信息载体；同步/异步还要通过实线/虚线表达，终态还要通过边框表达。
- 所有链接有可见 focus 样式。
- 长 URL 不直接展示；使用方法名、文件名或“查看代码”作为链接文字。
- 避免 JavaScript 依赖才可读到报告的核心内容。
