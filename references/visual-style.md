# 视觉与交互规范

## 总体风格

- 只使用 Light 主题：页面背景白色，正文深灰，禁止深色段落、深色代码块、暗色 SVG 背景。
- 接近 Notion/Linear 的克制文档感：内容宽度稳定、层级清晰、留白充足、边框轻、阴影弱。
- 正文 `14px`，行高 1.65；标题仅用于信息层级，不使用营销式超大标题。
- 使用低饱和蓝、绿、灰、橙作为语义色：蓝表示主路径/应用层，绿表示成功或终态，橙表示异步或注意，红只表示失败/阻断。
- 卡片圆角不超过 `8px`，不要形成卡片套卡片。

建议色板：

```css
:root {
  --page: #ffffff;
  --surface: #f8fafc;
  --border: #e2e8f0;
  --text: #1e293b;
  --muted: #64748b;
  --blue: #2563eb;
  --blue-soft: #eff6ff;
  --green: #15803d;
  --green-soft: #f0fdf4;
  --orange: #c2410c;
  --orange-soft: #fff7ed;
  --red: #b91c1c;
  --red-soft: #fef2f2;
}
```

## 离线自包含原则

最终 HTML 在断网环境双击打开仍可使用：

- 所有 CSS、JavaScript、图表、图标和代码片段都在单个 HTML 内。
- 禁止 `<script src>`、`<link href>`、`img src="http..."`、PlantUML URL、Mermaid CDN、远程字体、远程图片和 fetch/XHR/WebSocket。
- 图表必须作为内联 `<svg>` 插入。可以在生成阶段使用任意辅助工具，但最终产物仅保留预渲染的 SVG。
- SVG 必须有 `viewBox`、可缩放宽度、文本替代说明 `aria-label` 或 `<title>`，并使用模板的 lightbox 交互。

## 图表规则

所有图独立成卡片，包含：标题、阅读提示、图本体、图例（必要时）和证据链接。

### 系统总览

- 优先左到右阅读。
- 用清晰层次区分入口、Application、Domain、存储、外部依赖。
- 同步边使用实线，MQ/任务/重试使用虚线。
- 异步不应被隐藏在角落；标出发布与消费的真实方法。
- 使用有标题的分层泳道或分区带，不要只排列一串方框。每层包含业务职责短句、真实方法名或接口名，并在跨层边上标注动作。
- 入口、核心写入、外部依赖、异步收敛分别使用蓝、绿、灰、橙的低饱和底色；箭头以正交线为主，避免随意斜线。
- 节点需要三层文字层级：层标题 `14px/700`，核心模块或方法 `13-14px/700`，说明文字 `10-11px/400`。状态变更、外部调用和异步主题使用加粗或语义色强调，不能让所有文字同样粗细和字号。
- 连接线必须先在空白通道中布线，再放说明文字；说明文字不得覆盖节点、箭头或其他说明。跨越两层以上时使用固定边缘通道，不从其他节点中间穿过。
- 每一条有向关系都必须单独绘制并带明确箭头。禁止将多段关系合并为一条只有末端箭头的折线；没有箭头的线只能用于泳道、边框或非方向性关联。

### 实体关系

- 每个实体显示名称、关键 ID、状态/跟踪字段和关键外键。
- 关系边标注真实关联字段名。
- 实体过多时按聚合/模块拆图，不能缩小字体强行塞进一张图。
- ER 图的关系边使用菱形/箭头或 crow's foot 表达基数和方向；每条实际关联都必须有可见的关系标签。

### 状态机

- 一张图只表示一个实体。
- 终态使用双边框或绿色强调。
- 每条边使用触发方法名；不画无法确认的合法路径。

### 时序图

- 参与方顶部按调用方向排列，名称带仓库短名。
- 同步调用用实线箭头，异步发布/消费用虚线箭头。
- 使用明显的 `成功`、`失败`、`重试/补偿` 分段，而不是重叠的箭头。
- 一张图过大时，按“接入和校验”“持久化和外部调用”“异步收敛”拆开。
- 时序图必须采用泳道：每个参与方占固定列宽，顶部有色标题条，正文有浅色泳道底纹与虚线生命线。
- 不同参与方泳道必须使用可区分的低饱和底色，例如入口蓝、编排绿、核心逻辑橙、外部服务紫蓝、异步消费者浅红；对应标题使用同色系深色文字。不要把所有泳道画成同一种灰色。
- 每步使用带编号的小标签和一句真实的方法名；关键字段写入使用紧邻箭头的字段胶囊，而不是长段文本。
- 失败、重试、幂等、异步回调必须用独立的浅色分组框（`alt` / `retry` / `async`）表达，不能只在箭头旁补一行文字。
- 单图应优先呈现 6 到 12 步。如果主链路超过该范围，拆成“准备和写入”“外部调用和结果收敛”两张连续图；视觉上使用相同参与方顺序和颜色。
- SVG 需具备统一圆角、12px 以上图中文字、步骤编号、图例和足够留白。禁止只用简单矩形加直线作为最终交付图。
- 主路径、状态写入、外部调用、异步消息、失败补偿分别使用可区分但低饱和的蓝、绿、紫蓝、橙、红。颜色必须配合箭头、编号和分组框，不能只靠颜色传递信息。
- 泳道颜色只表示参与方；补充块、`alt`、状态保护、重试和异常说明不得复用任一泳道颜色。推荐使用浅黄表示补偿/分支、浅青表示状态保护/幂等、浅红表示失败终态。

### 字段生命周期

- 用从左到右的阶段展示首次写入、更新条件、复制/清空、终态值。
- 状态字段和业务标识字段分开展示，避免把多类字段塞进一条不可读流程。

## HTML 交互

`templates/report.html` 已提供下列交互，生成报告时不要移除：

- 固定左侧目录和 scrollspy。
- 图表点击或键盘 Enter/Space 打开 lightbox。
- 代码片段 `<details>` 折叠；鼠标悬停可见打开代码的 VS Code deep link。

生成内容需要：

- 每个一级章节使用稳定 `id`，并在侧边栏声明对应锚点。
- 每个可放大 SVG 包在 `.diagram-zoom` 中，带 `tabindex="0"` 和 `data-lightbox-title`。
- 代码片段使用 `.code-evidence`、`<details>`、`<pre><code>`，并包含可点击 deep link。
- 表格在窄屏时放入 `.table-wrap`，保持横向滚动而非压坏布局。
- 图下注释中的“证据”使用低对比度纯文本位置，不提供链接，也不使用蓝色。
- 代码导航必须使用独立的 icon+text 按钮，例如 `打开代码 ↗`；不能让方法名、证据名称或普通正文同时承担跳转动作。
- 对 `vscode://`、`cursor://` 等自定义协议按钮加入 `target="_blank"`。同时渲染一个可复制的回退命令，避免内嵌浏览器拦截协议时用户没有出路。
- 不提供“返回顶部”按钮。固定侧边栏目录已经覆盖页面级导航，避免在正文末尾增加无关控件。

## 可读性与无障碍

- 图中文字最小 `12px`，普通表格最小 `12px`。
- 颜色不作为唯一信息载体；同步/异步还要通过实线/虚线表达，终态还要通过边框表达。
- 所有链接有可见 focus 样式。
- 长 URL 不直接展示；使用方法名、文件名或“查看代码”作为链接文字。
- 避免 JavaScript 依赖才可读到报告的核心内容。
